# 物流混合检索 RAG：运行、验证与边界

更新日期：2026-10-19。当前工作区在 React 工作台之上增加混合检索，原 Agent 工具列表、确认建单、操作员状态机、数据库幂等与网页接口均保留。**这次新增功能完成本地验证；原 Railway/Dify 发布记录不等于本次 RAG 已云端发布。**

## 1. 当前实现

`search_sop` 的输入仍为 `query`、`top_k`（1～5，默认3）。新增机制：

1. 只读取 `docs/[0-9][0-9]_*.md` 十份 SOP，部署说明不会混入业务知识。
2. 按 Markdown 标题层级切分，每片正文最多700字符；长章节按换行/句号/分号附近切开，最多80字符重叠，不跨章节拼接。短章节没有重叠；700/80是字符数，不是 Token。
3. Embedding 使用兼容 OpenAI 的 `/embeddings` API，当前真实验证模型为 `BAAI/bge-m3`，1024维。检查数量、索引、维度、有限值和非零向量，不把错误响应入库。
4. Qdrant 保存向量和 `source/title/section/content/chunk_id/corpus_version/embedding_model`。检索采用余弦相似度；当前数据量小，支持服务端模式和持久化嵌入模式，不能由此声称完成大规模 ANN 或分布式性能验证。
5. BM25 和向量通道分别最多召回12个片段；BM25 保留原中文单字/相邻双字、英文数字词分词，语义通道默认最低余弦分数0.45。RRF 按 `Σ1/(60+rank)` 融合，不直接相加两种原始分数。融合后返回前 `top_k` 个片段，同一文档可能有多个章节；未加入 Cross-Encoder Reranker。
6. 输出兼容原 `source/content/score/truncated`，增加 `citation`、章节、双路分数、实际检索方式、降级原因与索引版本。RRF 分数不是概率。

订单、轨迹、草稿、工单及状态仍从 SQLite 工具读取。向量库只保存制度，不承担动态业务事实查询，更不执行建单或状态迁移。

## 2. 本机运行

从仓库根目录执行：

```powershell
python -m pip install -r requirements-dev.txt
# 按 .env.example 在被 Git 忽略的 .env 中配置 Embedding 凭证。
# 方式A：持久化嵌入模式，QDRANT_URL留空，适合单进程演示。
python -m order_api.rag_index
python -m order_api.rag_index --check
python -m order_api.run_demo
```

方式B：独立 Qdrant 服务：

```powershell
docker compose -p logisupply-rag -f compose.rag.yml up -d
# .env 中设置 QDRANT_URL=http://127.0.0.1:16333，再运行索引和API。
python -m order_api.rag_index
python -m order_api.run_demo
```

本机 Docker 引擎位于 WSL 时，可用 `wsl -d Ubuntu-24.04 -- docker compose -p logisupply-rag -f /mnt/d/大数据开发面试准备_两会话整理/logisupply-rag-agent/compose.rag.yml up -d`。Compose 仅将16333端口绑定到本机回环地址，数据保存在独立命名卷。服务器部署应另配置服务鉴权和网络访问边界。

`run_demo`、`serve` 和索引 CLI 会读取仓库根 `.env`，现有进程环境变量优先。直接使用 `uvicorn order_api.main:app` 时由调用方提供环境变量。密钥不进前端、不写报告、不放入镜像。

## 3. 索引更新与降级

语料内容、标题、模型、维度、模型地址和切分版本共同决定 collection 名称。先在显式索引命令中取得并验证全部向量，再写入对应版本；片段数量不完整时不视为就绪。相同内容重复执行会复用完整索引；删除文档会得到新版本，不会在新查询中混入旧文档。旧 collection 保留，不自动删除。

嵌入模式由一个进程独占目录；更新索引前停止 API，完成后重新启动。进程内部用锁串行保护 Qdrant 本地操作。多个 Worker/多副本应使用独立 Qdrant 服务；不能同时让 CLI 和 API 打开同一嵌入目录。服务端模式仍应在语料更新后重启 API，使 BM25 和向量通道使用同一份内容快照。

查询不会隐式全库重建或补做整库 Embedding。缺索引、Embedding 超时/限流/错误、向量库不可达时，返回章节 BM25，并标记 `degraded=true` 与公开错误码；不把上游错误正文、地址凭据写给用户。`RAG_MODE=bm25` 是主动关闭语义通道，不标记故障降级。依赖恢复后下一次查询重新尝试语义检索。

默认8秒为 Embedding/Qdrant 各自请求超时配置，不是整条 Agent 链路的严格总时限。并发、吞吐、费用与服务故障恢复时间尚未压测。

## 4. 复现验证

```powershell
python -m pytest --junitxml=evaluation/results/hybrid_tests.xml
python evaluation/hybrid_eval.py
python evaluation/hybrid_acceptance.py
# 可选真实模型工具循环：私有配置只读取 LLM_API_KEY/BASE_URL/MODEL。
python evaluation/hybrid_acceptance.py --llm-env <私有配置路径> --model Qwen/Qwen3-14B
cd web
npm test
npm run build
```

- `tests/test_hybrid_rag.py`：真实嵌入 Qdrant，使用明确标记的二维测试向量，验证持久化、融合、故障降级、无结果、版本隔离、向量验证、多线程及工单闭环；二维测试不能当语义效果证据。
- `evaluation/results/hybrid_retrieval.json`：真实 Embedding 与 Qdrant，25个既有问题＋10个同义改写，共35个固定开发题。原整篇 BM25 Top-1 文档命中28/35，混合检索33/35；两者 Top-3 至少命中一份预期文档均为35/35。章节BM25为31/35，纯向量33/35；混合并非在所有子集优于纯向量。多文档题另计算必要来源覆盖。
- 原文档级与新片段级 Top-3 的粒度不同；Top-1 按结果来源文档比较。新增改写题为人工设计的固定开发题，不能称为独立盲测或线上正确率。
- `hybrid_acceptance.json`：只有实际通过的本地 API/Embedding/Qdrant/模型检查才记通过；模型不选工具、编造草稿的失败摘要和来源说明见hybrid_failure_history.json；引用格式原始报告另保留，不用后续通过抹除风险。最终模型引用的文件与章节有效，但一次输出没有逐字保留citation格式，此差异在报告中单独记录。

天气、股票等无关问题也可能因普通词命中 BM25。当前由模型核对证据并拒答，不具有程序级语义拒答保证；SOP中的示例话术不能当成当前订单已发生的动作。来源可追溯也不等于每句话已被自动核验。
